---
description: Explain a task in plain English using the spec as context
---

1. Read `tasks/tasks.json`. Ask which task ID to explain (or infer from context).
2. Read the linked spec.
3. Explain the task in plain English:
   - What needs to be built
   - What the spec says about it
   - What files will likely be touched
   - What the acceptance criteria are (from the spec's Behavior and Error Cases)
   - Any known risks or dependencies

Keep it concise — one short paragraph per section.
